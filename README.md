# GEDCOM test files

Small synthetic GEDCOM files with known faults, for testing genealogy software: parsers, importers, converters and validators.

- 29 files, GEDCOM 5.5.1 and 7.0, most under 1 KB.
- Each file has one kind of fault (or none), described below and in [manifest.json](manifest.json).
- Every person, place and source is invented. No real family data.
- MIT licensed. Copy the files into your own test suite.

The files are generated by [scripts/build.mjs](scripts/build.mjs), so their exact bytes (character sets, byte order marks, line endings) can be reviewed and rebuilt. `.gitattributes` keeps Git from changing line endings in `.ged` files; if you copy them by other means, compare the byte counts in the manifest.

## How to use

Download a single file from the tables below, or clone the repository:

```sh
git clone https://github.com/thememorypalace/gedcom-test-files.git
```

`manifest.json` lists every file with its version, encoding, the fault codes it should trigger, and an explanation. A test can loop over it:

```js
import manifest from "./gedcom-test-files/manifest.json" with { type: "json" };

for (const entry of manifest) {
  const result = yourParser(readFileSync(entry.file));
  // entry.faults is empty for valid files
}
```

The fault codes are the ones used by [gedcom-tools](https://github.com/thememorypalace/gedcom-tools). Other validators name them differently; the explanations say what is wrong in plain words, so you can map them to your own codes.

## The files

### Valid files

These should load without errors. Use them as a baseline and as round-trip input.

| File | Version | Encoding | Fault codes |
| --- | --- | --- | --- |
| [551-minimal.ged](files/valid/551-minimal.ged) | 5.5.1 | UTF-8 | none |
| [551-family.ged](files/valid/551-family.ged) | 5.5.1 | UTF-8 | none |
| [551-date-forms.ged](files/valid/551-date-forms.ged) | 5.5.1 | UTF-8 | none |
| [70-minimal.ged](files/valid/70-minimal.ged) | 7.0 | UTF-8 | none |
| [70-family.ged](files/valid/70-family.ged) | 7.0 | UTF-8 | none |

**551-minimal.ged**: Smallest useful 5.5.1 file. Header with GEDC, CHAR and SUBM, one submitter, one person, trailer. A reader that fails on this file fails on everything.

**551-family.ged**: Three generations, 5.5.1. Five people in two families with places, a source citation, a note split with CONC and CONT, and the common date modifiers (ABT, BEF, BET AND, FROM TO). Non-ASCII names in UTF-8.

**551-date-forms.ged**: Unusual but valid 5.5.1 dates. Dual year (1648/9), Julian calendar escape, interpreted date with phrase, a date phrase alone, B.C., CAL and EST. All valid in 5.5.1; a checker should not call them errors, and a 5.5.1 to 7.0 converter has to translate most of them.
Known difference in gedcom-tools 0.1.0: reports the dual year 11 FEB 1648/9 as a bad date. That is a bug in the checker, not in this file. Fixed in gedcom-tools 0.1.1.

**70-minimal.ged**: Smallest useful 7.0 file. A 7.0 header has no CHAR and no SUBM requirement; the file is always UTF-8.

**70-family.ged**: Three people, 7.0. Uses the 7.0 features that 5.5.1 readers often stumble over: SCHMA with an extension tag, LANG as a BCP 47 tag, SNOTE, EXID with TYPE, a value starting with an escaped @@, PEDI under FAMC, a date with PHRASE and an OBJE record with a media type.

### Broken links

Pointer problems between records.

| File | Version | Encoding | Fault codes |
| --- | --- | --- | --- |
| [broken-pointer.ged](files/links/broken-pointer.ged) | 5.5.1 | UTF-8 | `broken_pointer` |
| [duplicate-ids.ged](files/links/duplicate-ids.ged) | 5.5.1 | UTF-8 | `duplicate_id` |
| [one-sided-link.ged](files/links/one-sided-link.ged) | 5.5.1 | UTF-8 | `one_sided_link` |
| [empty-family.ged](files/links/empty-family.ged) | 5.5.1 | UTF-8 | `empty_family` |
| [own-ancestor.ged](files/links/own-ancestor.ged) | 5.5.1 | UTF-8 | `own_ancestor` |

**broken-pointer.ged**: Pointers to records that do not exist. I1 points to family @F9@ and F1 points to wife @I99@; neither record exists. Typical after someone deletes records by hand or exports part of a tree.

**duplicate-ids.ged**: Two records with the same ID. @I2@ is used twice. Which one a pointer means is undefined; programs silently keep the first, keep the last, or merge them. Common when two files are pasted together.

**one-sided-link.ged**: Links that only point one way. I1 says it is a spouse in F1, but F1 has no HUSB or WIFE pointing back. F1 lists I2 as a child, but I2 has no FAMC. GEDCOM 5.5.1 expects both directions; readers that follow only one side lose people.

**empty-family.ged**: A family without members. F1 has a marriage but no husband, wife or children. Usually left behind after people were deleted.

**own-ancestor.ged**: A person who is their own ancestor. Mira is Lars's child and Lars is Mira's child. Any code that walks ancestors or descendants without a visited set loops on this file.

### Impossible dates

Dates that do not exist, and dates that cannot be true together.

| File | Version | Encoding | Fault codes |
| --- | --- | --- | --- |
| [invalid-calendar-dates.ged](files/dates/invalid-calendar-dates.ged) | 5.5.1 | UTF-8 | `bad_date` |
| [death-before-birth.ged](files/dates/death-before-birth.ged) | 5.5.1 | UTF-8 | `death_before_birth` |
| [family-chronology.ged](files/dates/family-chronology.ged) | 5.5.1 | UTF-8 | `child_before_parent`, `parent_too_young`, `born_after_mother_death` |
| [too-old.ged](files/dates/too-old.ged) | 5.5.1 | UTF-8 | `too_old` |

**invalid-calendar-dates.ged**: Dates that do not exist or are not GEDCOM. 31 FEB, 31 APR and day 0 do not exist. 12/03/1921 is ambiguous (December or March) and not a GEDCOM date. JULY 4 1922 uses a full month name in the wrong order. 30 APR 1901 is the one valid date, as a control.

**death-before-birth.ged**: Death before birth. Usually a typo in the year, or the birth date of a child entered on the parent.

**family-chronology.ged**: Children that cannot belong to these parents. Otto (1899) is born before both parents. Anna (1910) has a father of 9 and a mother of 7. Jan (1935) is born five years after his mother died in 1930. Typical of two people with the same name merged into one.

**too-old.ged**: A lifespan of 150 years. Born 1700, died 1850. Mostly a father and son with the same name taken for one person.

### Character sets

ANSEL, Windows-1252, UTF-16 and broken UTF-8. The same four invented names appear in most of them, so the decoded result is easy to compare.

| File | Version | Encoding | Fault codes |
| --- | --- | --- | --- |
| [ansel.ged](files/encoding/ansel.ged) | 5.5.1 | ANSEL | `encoding_ansel` |
| [ansel-label-utf8-bytes.ged](files/encoding/ansel-label-utf8-bytes.ged) | 5.5.1 | UTF-8 (labelled ANSEL) | `encoding_mislabeled` |
| [windows-1252.ged](files/encoding/windows-1252.ged) | 5.5.1 | Windows-1252 | `encoding_ansi` |
| [no-char-line.ged](files/encoding/no-char-line.ged) | 5.5.1 | Windows-1252 (no CHAR line) | `encoding_no_char` |
| [invalid-utf8.ged](files/encoding/invalid-utf8.ged) | 5.5.1 | Windows-1252 (labelled UTF-8) | `encoding_mislabeled` |
| [garbled-utf8.ged](files/encoding/garbled-utf8.ged) | 5.5.1 | UTF-8 (double encoded) | `garbled_chars` |
| [utf16le-bom.ged](files/encoding/utf16le-bom.ged) | 5.5.1 | UTF-16LE with BOM | none |
| [utf8-bom.ged](files/encoding/utf8-bom.ged) | 5.5.1 | UTF-8 with BOM | none |

**ansel.ged**: ANSEL with combining marks. CHAR ANSEL, as written by older genealogy programs. In ANSEL the accent byte comes before the letter: é is 0xE2 0x65, ü is 0xE8 0x75. Ł (0xA1), ł (0xB1) and ß (0xCF) are single bytes. Decoded correctly, the names are Hélène Exemple, Jürgen Müller, Łucja Przykład and François Groß. This is not a fault in the file; checkers report it as information because many readers do not support ANSEL.

**ansel-label-utf8-bytes.ged**: Header says ANSEL, bytes are UTF-8. A file that was converted to UTF-8 without updating the CHAR line. A reader that trusts the header turns every accented letter into two wrong characters.

**windows-1252.ged**: Windows-1252 labelled ANSI. CHAR ANSI is not a 5.5.1 value but is common in files from Windows programs. é is the single byte 0xE9 and € is 0x80. Łucja and Przykład cannot be written in Windows-1252, so that person is left out.

**no-char-line.ged**: No CHAR line. 5.5.1 requires CHAR. Without it a reader has to guess; here the bytes are Windows-1252.

**invalid-utf8.ged**: Header says UTF-8, bytes are not. The single byte 0xE9 for é is not valid UTF-8. A strict UTF-8 decoder either fails or produces the replacement character U+FFFD.

**garbled-utf8.ged**: Double-encoded UTF-8 (mojibake). Valid UTF-8, but the names read HÃ©lÃ¨ne and MÃ¼ller: the text was decoded as Windows-1252 and encoded to UTF-8 a second time. Jürgen is correct, as a control. The damage is reversible when every affected sequence maps back exactly.

**utf16le-bom.ged**: UTF-16 little endian. CHAR UNICODE with a byte order mark, as written by some Windows programs. Every ASCII character is followed by a zero byte, which breaks readers that look for 0 HEAD in the raw bytes.
Known difference in gedcom-tools 0.1.0: decodes the file correctly but does not see the CHAR line in UTF-16. That is a bug in the checker, not in this file. Fixed in gedcom-tools 0.1.1.

**utf8-bom.ged**: UTF-8 with byte order mark. Valid. The three bytes EF BB BF come before 0 HEAD; readers that compare the first line literally fail to see the header.

### File structure

Problems in the line structure rather than the content.

| File | Version | Encoding | Fault codes |
| --- | --- | --- | --- |
| [missing-trlr.ged](files/structure/missing-trlr.ged) | 5.5.1 | UTF-8 | `trlr_missing` |
| [after-trlr.ged](files/structure/after-trlr.ged) | 5.5.1 | UTF-8 | `after_trlr` |
| [no-version.ged](files/structure/no-version.ged) | unknown | UTF-8 | `version_missing` |
| [level-jump.ged](files/structure/level-jump.ged) | 5.5.1 | UTF-8 | `level_jump` |
| [whitespace-and-line-endings.ged](files/structure/whitespace-and-line-endings.ged) | 5.5.1 | UTF-8 | `line_endings`, `blank_lines`, `leading_space` |
| [conc-in-v7.ged](files/structure/conc-in-v7.ged) | 7.0 | UTF-8 | `conc_in_v7` |
| [no-head.ged](files/structure/no-head.ged) | unknown | UTF-8 | `head_missing` |

**missing-trlr.ged**: No trailer. The file stops without 0 TRLR, often a sign that an export or upload was cut off.

**after-trlr.ged**: Records after the trailer. Two files glued together, or an editor that appended records at the end. Most readers stop at TRLR and lose I2.

**no-version.ged**: No GEDC.VERS. Without a version a reader cannot tell 5.5.1 from 7.0.

**level-jump.ged**: A level that skips one. DATE is at level 3 directly under a level 1 line. The structure is undefined; some readers attach it to BIRT, others drop it.

**whitespace-and-line-endings.ged**: Mixed line endings, blank lines and indentation. CRLF and LF in one file, empty lines, and lines indented with spaces. 5.5.1 allows none of the last two, but files edited by hand look like this.

**conc-in-v7.ged**: CONC in a 7.0 file. CONC does not exist in 7.0. Seen in files where only the version number was changed.

**no-head.ged**: No header. The file starts with a record. Without HEAD there is no version and no character set.

## Checking the descriptions

```sh
npm install
npm test
```

This runs every file through gedcom-tools and checks that each listed fault is reported, and that the valid files give no errors or warnings. Where gedcom-tools itself gets a file wrong, the manifest says so under `knownDifferences` instead of changing the file to suit the tool.

## Contributing

New cases are welcome, especially faults found in real exports from genealogy programs. Please rebuild them from invented data: never submit a file with real people in it, living or dead. Add the case to `scripts/build.mjs`, run `npm run build` and `npm test`, and open a pull request.
